# Design System: Shortcuts website

## Overview

**Creative North Star: "A shortcut, close to the work."**

Expand the existing native app identity through its blue Command icon, platform typography and quiet hierarchy. Pale neutral surfaces, precise blue actions and genuine localized app images make the product recognizable without creating a second brand.

The system is light, restrained and readable. Spacing separates content; thin borders and tonal changes identify controls and groups. Native app materials remain inside the product images; the website itself uses flat surfaces.

**Key Characteristics:**
- The existing blue Command app icon and platform system family.
- A single functional blue accent on cool neutral surfaces.
- Uncropped, localized production-view renders with full-size access.
- Visible interaction states, restrained motion and responsive reading widths.

The record is extracted from `assets/site.css`, the two localized landing pages and the shared 404 page. The frontmatter owns the implemented values. Surface sequence and conversion goals remain in `surface.md`; product and release facts remain in `PRODUCT.md`.

## Colors

One deliberate blue accent sits on cool near-white surfaces with dark navy text.

### Primary

- **Action blue** (`accent`) identifies downloads, ordinary links, step numbers and keyboard combinations. **Deep action blue** (`accent-hover`) is the download hover state.
- **Soft selection blue** (`soft-blue`) fills pressed modifier controls. **Selection ink** and **selection fill** supply the browser text-selection pair.

### Neutral

- **Canvas** is the page background; **surface** is the white demo and Studio section.
- **Ink** is the main reading color; **muted** carries supporting text, navigation and captions. **Scrollbar** supplies the thumb color against the canvas.
- **Line** separates sections and outlines controls; **list divider** is the lighter separator between demo results.
- **Panel stage** and **practice stage** are distinct cool surfaces behind the genuine app images.

**The Color has a job Rule.** Use the accent for actions, links, key combinations and selected modifier controls; use neutral tones to organize reading.

There is no named numeric tonal scale in the implementation. The sidecar records only observed colors; it does not promote generated intermediate swatches into product tokens.

## Typography

**Display and Body Font:** the existing platform system stack from the frontmatter. No external font is loaded. The explicit native identity commitment applies to display text as well as interface copy.

The hierarchy is weight- and size-led, with balanced heading wraps and modest negative heading tracking. Paragraphs normally stop at 70ch; the hero introduction is limited to 35ch, widening to 42ch on mobile. The primary heading is limited to 18ch on desktop and 19ch on mobile.

### Hierarchy

- **Display / display-mobile:** the hero promise; the mobile role replaces the desktop role at the single-column breakpoint.
- **Display-fallback:** the larger shared h1 rule, currently visible on the 404 page. The landing hero deliberately overrides it.
- **Headline / headline-source:** fluid section headings and the fixed smaller open-source heading.
- **Heading / heading-detail:** step and demo headings, plus the smaller Studio detail headings.
- **Brand / brand-mobile:** the name beside the existing icon, with its own tracking and responsive size.
- **Lead / lead-compact:** every direct paragraph in the hero introduction, including release metadata and the install note. These specific rules override the generic metadata and label sizes there.
- **Body / body-compact / body-small:** main reading, mobile body and step/disclosure copy, and denser navigation/list/detail copy.
- **Label / metadata / caption:** supporting copy, compact release/status/footer copy, and image captions. Mobile navigation uses the label size.
- **Action / disclosure / step-number:** emphasized download labels, native disclosure summaries and tabular ordered-list counters.
- **Path:** medium emphasis for a path within installation instructions; size and line-height inherit from the surrounding copy.
- **Key-symbol / key-name / keyboard-chord:** actual modifier symbols, their legible names, and shortcut notation. The name role is the corrected 12px implementation, not the superseded 10px value.

**The Native continuity Rule.** Preserve the existing app icon and the explicitly selected platform system font stack.

## Layout

The shared container caps at 1160px. Desktop gutters are 36px per side, become 24px at 900px, and become 18px at 700px. The desktop header has a 104px minimum height, reduced to 88px on mobile. Its app icon changes from 43px to 36px.

The hero uses a 0.95:1.05 split with a 62px gap. Other desktop content grids use equal columns, a 0.9:1.1 mechanism split, a 1:1.1 installation split and a 0.75:1.25 facts split. Their separate gap values are recorded in the spacing tokens. Studio details use three equal columns. At 900px gaps and controls compact; at 700px these grids become one column. The mobile hero retains a 32px gap; section heading pairs use an 18px gap.

Repeated sections use the `section` spacing token, reduced to `section-mobile`. Studio uses a white full-width band with centered, inset content; its vertical padding is `practice-block`, reduced to `mobile-practice-block`. Logical `padding-block` is intentional: the inner shared container supplies horizontal gutters.

Images remain full width with automatic height and no crop. The image stage minimum height changes from 250px to 130px on mobile. Dense native content has a separate full-size image link. Secondary page anchors hide on mobile while source and language links remain visible. Text and direct download links remain usable without JavaScript.

## Elevation & Depth

The website has no box-shadow, backdrop blur or gradient. Depth comes from canvas-to-surface contrast, light image stages and thin separators. The production app images retain the app’s own materials; those materials do not become CSS treatments for the website.

**The Flat surfaces, clear groups Rule.** Use tonal surfaces and thin borders for the website; do not add shadows to establish its hierarchy.

## Shapes

Rounded rectangles distinguish the language link, modifier keys, download action and surface containers. Their four existing radii are listed in the frontmatter. One-pixel borders define language and modifier controls, the demo card, list dividers and disclosure rows. Screenshot stages clip at the surface radius while preserving the image aspect ratio. Full-width sections themselves remain square.

## Components

### Download action

A filled accent link with white text, the existing inline download SVG, `button` rounding and a 50px minimum height. The SVG is 18px; label and icon have a 10px gap. Hover deepens the blue. The only transition is background color over 140ms with ease-out. This is the only filled call-to-action variant.

### Modifier controls

Each real modifier has a symbol and a name; default styling uses canvas, ink and line. Hover changes the border to accent. Pressed state uses soft blue, accent text and an accent border, with `aria-pressed` exposing the state. Controls start at 66px minimum width and height; minimum width reduces to 53px at 900px and 52px at 700px. Compact inline padding becomes 7px. Background and border colors transition over 140ms with ease-out. The example is click-driven and captures no operating-system shortcuts.

### Demo card and result rows

The white, outlined demo surface uses the `surface` radius and the recorded desktop/compact padding. Result rows have light top dividers, a 15px text size, shortcut notation on the opposite edge and 10px vertical padding. The list reserves 208px of height; a polite status region reserves 40px. No input field, generic chip or additional card variant exists in the site.

### Navigation and language link

Quiet, un-underlined navigation uses muted text and becomes accent on hover. The language link remains ink-colored and outlined with its smaller radius. Ordinary content links retain an underline with a 0.2em offset; thickness increases from 1px to 2px on hover. Header layout wraps as needed, with a reduced mobile type size and gap.

### Native disclosures

Built-in `details` and `summary` supply open/closed behavior and the browser’s marker. Summaries use the disclosure type role and a pointer cursor; rows use a 1px lower rule and 20px block padding, except the first row’s top padding. Revealed copy uses body-compact and muted text. There is no invented animated accordion or custom marker.

### Image stages and provenance

The four localized app images are offscreen renders of native production views, prepared with synthetic public demonstration data. They are not captured user sessions and are not illustrated substitutes for the UI. The existing app icon comes from the app’s iconset generated by `scripts/create-icon.swift`. No image-generation prompt applies to these code-rendered assets. The site supplies localized alternative text, captions and full-size links. The JavaScript unavailable-image fallback is an error state, not a pending asset deliverable.

### Focus and motion

Links, buttons and disclosure summaries share a 3px accent outline with a 5px offset under `:focus-visible`. The skip link appears on focus. Anchor scrolling is smooth with 28px scroll padding. Reduced-motion preference disables smooth scrolling and all transitions. There are no entrance animations or motion-only cues.

## Do's and Don'ts

### Do:
- Do preserve the blue Command icon and the platform system font family.
- Do show actual localized app renders at their complete aspect ratio, with meaningful alternative text and a full-size link.
- Do retain the accent focus ring, pressed-state semantics and reduced-motion behavior.
- Do use the documented responsive roles and spacing rather than adding an unrelated scale.

### Don't:
- Don’t introduce an external font or substitute a new app identity.
- Don’t use keyboard glyphs as decoration; they identify actual modifiers and shortcut combinations here.
- Don’t add decorative glass, gradients or shadows to the website’s flat surfaces.
- Don’t use fabricated app screens or style an unavailable-image fallback as a screenshot.
